# MoviePilot 旧媒体季度修复助手

## 工作位置

修复发生在媒体已经上传并生成 STRM 之后：

`下载完成 -> MoviePilot 整理/上传 -> 修复助手扫描 -> 人工确认 -> 暂停 Symedia -> CloudDrive2 网盘真文件分季/改名 -> 删除并重建本地 STRM/NFO/图片 -> 恢复 Symedia -> Emby 重扫`

候选发现先扫描 Symedia 的本地 STRM 索引，因此不会因遍历整块 CloudDrive2 超过网页反向代理超时。真正预览和执行时仍会重新读取 CloudDrive2 网盘真文件，并要求视频数量、连续集号和 TMDB 总数全部吻合；本地索引只能让项目进入候选列表，不能授权修改。

0.4.1 同时支持叠加污染清理：如果官方每一集都已完整存在，但某些季度还包含超出 TMDB 集数范围的旧绝对集号，修复端会再次核验网盘真文件，把多余视频移动到独立隔离挂载，不直接删除，然后重建 STRM/NFO/图片。任何缺集或有效集号多版本冲突都会停止自动清理。

0.4.2 增加按 TMDB ID 持久保存的人工季度集数规则。TMDB 条目缺集时，在黄色候选右侧点击“设置集数”，单季填写 `38`，多季填写 `20,20,18`。人工规则优先于 TMDB 缓存，扫描结果会标记“人工覆盖”；删除规则后才恢复使用 TMDB。规则只改变安全核对基准，不会绕过连续集号、无重复、网盘真文件数量和不覆盖目标文件等安全检查。

它不会介入正在下载或搬运的源文件。只处理已经完整进入 `symedia_gd/tvshows` 的项目；执行期间暂停 Symedia，避免“一边移动一边生成 STRM”的竞争问题。

## 安全边界

自动修复必须同时满足：

1. 只有一个源季度；
2. 集数严格为 `E01..EN`，无缺集、无重复；
3. `N` 与 TMDB 所有正常季度集数总和完全一致；
4. 网盘视频数量也与 TMDB 总数完全一致；
5. 目标文件不存在，不会覆盖任何已有文件。

任何一项不满足都标为黄色，只允许查看，不允许自动修复。宝可梦这类“发行分部与 TMDB 季度体系不同、总集数也不一致”的资源属于黄色项目，必须先建立人工边界规则。

## 部署组成

- MoviePilot 插件：`moviepilot/plugins/tvseasonrepair`
- MoviePilot 挂载示例：`moviepilot/docker-compose.season-repair.example.yml`
- Emby 本地修复端：`compose/emby-tg-notifier/app/season_repair.py`
- 修复端数据：通知程序的 `data/season-repair/`，包含压缩备份和可回滚移动清单
- 通讯密钥：通知程序的 `data/season_repair_token`，权限为 `0600`，不要提交到 GitHub

MoviePilot 插件页提供：

1. 扫描现有媒体库；
2. 单项只预览；
3. 单项修复；
4. 批量预览全部绿色项目；
5. 批量修复全部绿色项目；
6. 按动作号回滚。

插件主页只保留带日期的两行内最新状态和分类统计。扫描结果、扫描日志、处理中、成功、失败、预览/回滚日志以及可回滚记录均收进折叠分类面板；每条详细记录包含开始时间、结束时间、耗时和结果。

实际修复前必须先完成同一项目的只读预览；预览授权 30 分钟后失效。批量修复同样必须先执行“预览全部绿色项目”，避免误触后直接改动网盘。

修复开始时会登记一小时的维护抑制窗口。该剧因文件重排和 Emby 重扫产生的 Webhook 不进入 Telegram 入库批次，避免把旧集号误报成新入库；真实下载入库不受影响。

从插件页点击“确认修复”后，插件会自动重新执行一次只读预览，通过后才把任务交给后台串行处理。页面中的“修复任务”卡片保留最近 50 条任务，并显示排队中、正在预览、整理中、成功整理或整理失败及具体原因。MoviePilot 原生插件页不会主动刷新，关闭后重新打开即可读取最新状态。

扫描器只把“所有剧集连续堆在一个 Season 目录中”的媒体列为季度修复候选。已经存在两个或更多 Season 目录的媒体，即使文件集号与 TMDB 分季存在差异，也可能是特别篇、绝对集号、其他分季顺序或重复片源；插件会统计并跳过，不再把它误列为可修复项目。

服务端查找剧集根目录时会在发现 `{tmdb-id}` 目录后停止继续下钻。扫描接口在线程池运行，不会阻塞通知程序的 Webhook；网盘真文件只在预览/执行指定候选时读取。

首次扫描需要读取所有剧集的 TMDB 季度数据，耗时约几十秒。数据会缓存，后续扫描会明显更快。
